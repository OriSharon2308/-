# מדריך-כלים לכתיבת שיעורי-זהב

**זה הקובץ היחיד שצריך לקרוא על הכלים.** כל מה שכאן נלמד בפועל מקריאת `board.js`, `widget-kit.js`, `app.js`, `learn-board.html` ו-`lib/board-tools.js` — אין צורך לפתוח אותם שוב. כל שורה כאן היא מלכודת שכבר הפילה שיעור.

---

## הלוח — מערכת הקואורדינטות

- מרחב לוגי ‎**1000×560**‎ (הלוח רץ ב-`fit:"fill"`). הטווח המותר: **x בין 40 ל-960** · **y בין 60 ל-520**. אל תשים טקסט מתחת ל-y=505 — הילד לא יראה אותו.
- **צורות, `write_text`, `draw_exercise`:** ‎x,y = **מרכז** הפריט.
- **ווידג'טים אינטראקטיביים** (`render_widget`, `ten_frame`, `mult_array`, `hundred_chart`, `interactive_fraction`, `clock_interactive`, `money_coins`, `base_ten_builder`, `number_line_interactive`): ‎x,y = **הפינה השמאלית-העליונה**, וצריך גם `w` ו-`h`.
- מסך שמכיל `draw_exercise` עובר `arrangeBoard → fitView` ומתכווץ אוטומטית. מסכי-הוראה מוצגים 1:1 — שם החישוב חייב להיות מדויק.

## תשובות — איך הילד מקליד, ואיך המערכת משווה

- **המקלדת ב-`kind:"number"` היא ספרות בלבד.** הילד **לא יכול** להקליד `<`, `>`, `=`, או אות. אל תבקש סימן.
- `parseAnswerToNumberOrFraction` עושה `s.replace(",", ".")` — כלומר **"1,800" נקרא כ-1.8**. לעולם אל תכתוב פסיק-אלפים בתשובה, ואל תציג אותו בטקסט שהילד מעתיק ממנו. בדברי-המורה ובכיתוב — מותר.
- `answersMatch` מנרמל שברים למספר: תשובה `"2/3"` תקבל גם `"4/6"`. **העדף תשובה שהיא מספר שלם** (מונה, מכנה, גורם-הרחבה) על פני שבר.
- מספרים מושווים ב-`parseFloat` → `"34.5"` ו-`"34.50"` שקולות. בטוח.
- `kind:"text"` מושווה כמחרוזת **מדויקת** → מילה אחת בלבד (כן/לא/כפל/חילוק), ותמיד אמור לילד במפורש מה לכתוב.
- הוולידטור מפרש `a/b` בתוך `text` כ**חילוק** — אל תכתוב שבר עירום בטקסט של תרגיל.

## הטיית-מגדר

- צורת-לוכסן (`מוכן/ה`, `נסה/נסי`) מוטית אוטומטית ב-`reply`, וגם ב-`text`, `hint`, `praise`, `title`, `label`, `html`, `note`.
- הכלל דורש אותיות עבריות משני צדי הלוכסן — ולכן **"3/8" לא נפגע**.
- גם טקסט בתוך `html` של `render_widget` מוטה. כתוב שם צורות-לוכסן כרגיל.

## `render_widget` — מתי ואיך

רק כשאין כלי מוכן שמתאים. ה-HTML חייב להיות **עצמאי לגמרי**: בלי משאבים חיצוניים, בלי CDN, בלי פונטים. SVG נבנה ב-`createElementNS`. אם הילד אמור "לענות" מתוך הווידג'ט — `postMessage('vela:correct')`.

## המבנה הקבוע של שיעור

```json
{ "topic": "<שם הנושא בדיוק כמו במערך>", "lesson": 1, "title": "<מהמערך>",
  "phases": {
    "instruct":    [ {"reply":"…","toolCalls":[…]}, … ],
    "guided":        {"reply":"…","toolCalls":[…]},
    "independent":   {"reply":"…","toolCalls":[…]} } }
```

- `instruct` — **מערך של 3–6 מסכים**, רעיון אחד למסך.
- `guided` — **בדיוק `draw_exercise` אחד** + מניפולטיב-עזר לצדו.
- `independent` — **2–3 `draw_exercise`**. הראשון עם עזר, האחרון בלי.
- כל `draw_exercise` חייב `hint` ו-`praise`. ה-`hint` מכוון לדרך ו**אינו מכיל את התשובה**. ה-`praise` מחמיא על מה שהילד *עשה*.
- אורכים: `reply` ≤ 450 תווים · `hint` ≤ 220 · `praise` ≤ 140.

## הבדיקה

```bash
node scripts/check-golden.js <כיתה> --topic=<תחילית-שם-הקובץ>
```

`--topic` מסנן לקבצים שלך בלבד. בלעדיו תראה עשרות ממצאי "חסר שיעור-זהב" של נושאים שסוכנים אחרים כותבים במקביל, ותבזבז זמן על רעש.

## חוקי-הכתיבה (תמצית מ-SKILL.md — אין צורך לפתוח אותו)

1. **מהמוחשי אל הסמל.** המסך הראשון הוא הדמיה או כלי — לא הגדרה ולא תרגיל.
2. **מניפולטיב לעולם לא מסגיר תשובה.** השאלה נמצאת רק ב-`draw_exercise`.
3. **כלי-עזר צמוד** בשלב המודרך ובשאלה הראשונה של העצמאי; בסוף — בלי.
4. **שאלה אחת בכל פעם.** לא ערימה על מסך.
5. **כל שיעור נשען על הקודם**, ושיעור 1 מתחבר ל-`entry` של הנושא.
6. **התרגיל העצמאי אינו עותק** של הדוגמה הפתורה — אותה מיומנות, מספרים אחרים.
7. **שפה של ילד:** משפטים קצרים, מילות יום-יום, בלי מילים גבוהות. הלוח מדבר — המורה מכוון.
